GIT AND GITHUB NOTES:

GIT is a free , open source distributed version control system(DVCS) which allows us to track changes in files over time, allowing developers to maintain their project history, compare versions , collaborate and recover the previous versions.

ex:- In data science, when you modify a machine learning model's train.py file, Git helps you track what changed, when it changed, and who made the change.

Key terms:
- Version control: Tracking changes to files over time.
- Distributed: Every developer can have a complete local copy of the repository and its history.
- Commit: A recorded snapshot of changes.


Repository: 

a storage location that contains your project files and, when managed by Git, tracks their version history.


Suppose you are building a machine learning project to detect offensive comments.
Comment-Moderation-System/
├── train.py
├── app.py
├── preprocessing.py
├── requirements.txt
├── README.md

- train.py — trains your machine learning model.
- app.py — runs your application.
- requirements.txt — lists Python dependencies.
- README.md — explains the project.
- .git/ — stores Git's repository data and version history.


Types of repositories
1. Local repository: The Git repository on your computer.
2. Remote repository: A repository hosted on a server or platform such as GitHub.

How it works
You edit a file → Git tracks the changes → you commit a snapshot → you can inspect or restore earlier versions.

Remember: A project folder contains your files; when you initialize Git in that folder using git init, it becomes a Git repository.

Key points:

git status is a Git command that shows the current state of your working directory and staging area, including which files are modified, staged, untracked, or ready to be committed.

 Status	        Meaning
Modified   -	A tracked file has changed since its last committed version.
Untracked  -	A new file is not yet tracked by Git.
Staged     -    A change is selected for the next commit.
Clean	   -    No pending changes are reported in the working tree or staging area


git add is a Git command that stages new or modified files, selecting the changes you want to include in your next commit. In simple terms, it moves changes from your working directory into the staging area.

Command	Purpose
git add train.py	Stage one specific file
git add .	Stage changes under the current directory
git add *.py	Stage matching Python files in the current directory
git add -A	Stage additions, modifications, and deletions across the working tree

Industry practice: Prefer adding specific files when you need precise control over a commit. Before using git add ., check git status to avoid accidentally staging datasets, model files, or other unwanted content.


git commit is a Git command that records a snapshot of the changes staged in your repository, creating a permanent entry in the project's version history.

In simple terms, git add selects the changes, and git commit saves those selected changes in Git history.

git commit —> records the staged changes.

-m —> allows you to provide a commit message.

"Your commit message" —> briefly describes the changes.

A commit contains information such as:
- A unique commit identifier (hash).
- The author and timestamp.
- The commit message.
- References to the project's recorded content.

Industrial commit message practices
A commit message should clearly explain the change.

Weak message	Better message
changes  	Fix missing-value handling
update	        Add model evaluation metrics
final code	Add text preprocessing pipeline
bug fixed	Fix prediction label mapping


Command	                            Purpose
git commit -m "message"   -	Commit staged changes
git log --oneline	  -      View concise commit history
git show	          -    Inspect the latest commit
git status	          -    Check the current state
git diff --staged	  -    Review staged changes before committing

A commit is local until you push it to a remote repository. Also, commits do not automatically include every modified file—only the changes staged for that commit.

git restore --staged is a Git command that removes changes from the staging area without discarding the changes in your working directory.

Command                           	Effect
git restore --staged train.py	 ->     Unstages changes; keeps working-file edits
git restore train.py	         ->   Discards unstaged changes to a tracked file, restoring it from the index
git reset	                ->      Moves the current branch reference or, depending on options, changes the staging area
git commit	                ->       Records staged changes in repository history

git restore train.py can discard work you haven't committed. Check git status and git diff before using it.
